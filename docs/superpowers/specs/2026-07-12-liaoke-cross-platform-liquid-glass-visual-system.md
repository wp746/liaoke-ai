# 燎客跨端 Liquid Glass 视觉与动态系统

> **状态**：已批准，正式锁定
> **生效日期**：2026-07-12
> **适用产品**：用户端小程序、商家端小程序、平台管理后台
> **适用行为**：新增、删除、修改、查询任何页面、模块、组件和业务状态
> **基准实现**：`src/prototype/`
> **基准资产**：`public/brand/ip-liaoxiaoxing/scene-library/`
> **开发交接**：`docs/brand-ip/08-mini-program-development-handoff.md`

## 1. 规范效力

本文件不是一次性原型说明，而是燎客产品长期视觉治理标准。开发公司、内部产品、设计、前端和外包团队均必须执行。

规范优先级从高到低为：

1. 本文件的强制规则与 Token。
2. `docs/brand-ip/08-mini-program-development-handoff.md` 的实施和验收规则。
3. `src/prototype/` 中已批准的组件、样式和交互实现。
4. `artifacts/screenshots/` 中的基准截图。
5. 单页 PRD 中的局部视觉描述。

如旧文档、旧截图或旧资产与本文件冲突，以本文件为准。任何偏离必须先提交视觉变更说明和对比稿，经燎客负责人书面批准后才能实施。

## 2. 产品视觉定位

燎客的视觉定位是：

> 橙金火光品牌气质 + 暖白 Liquid Glass + Fluent Acrylic 信息层级 + 燎小星场景化陪伴。

目标不是复刻苹果或微软，而是形成燎客自己的“凝光玻璃”语言：

- 温暖、克制、高级，不做冷蓝科技皮肤。
- 有透明、折射、柔光和纵深，但信息永远清楚。
- 有互动和生命力，但不让动效干扰核销、支付、输入和后台操作。
- 用户端更有情绪价值，商家端更有效率，平台后台更专业。
- iOS 与 Android 使用同一布局、尺寸、内容层级和动效参数。

## 3. 三端共同原则

所有端必须满足：

- 只使用本规范定义的品牌色、圆角、材质、阴影、字阶和动效。
- 所有可见容器均使用圆角；不出现生硬直角卡片。
- 主界面不得出现卡片套卡片造成的层级堆叠。
- 一个页面只保留一个主视觉焦点和一个主 CTA。
- 玻璃是层级工具，不是装饰滤镜；表格、表单和关键数字优先保证可读性。
- 新业务对象必须先映射到现有 `RewardGlyph` 语义，不得随意下载或绘制不同风格图标。
- 所有新增页面必须从共享组件和 Token 构建，禁止复制 CSS 后单页改色、改圆角或改动效。

三端强度差异：

| 端 | 玻璃强度 | IP 强度 | 信息密度 | 主要目标 |
| --- | --- | --- | --- | --- |
| 用户端 | 高，但保持克制 | 高，按场景变化 | 低至中 | 亲和、引导、奖励感 |
| 商家端 | 中低 | 中，关键节点出现 | 中至高 | 快速判断、快速操作 |
| 平台后台 | 低 | 低，仅品牌和关键空态 | 高 | 管理效率、审计、风险识别 |

## 4. 基础设计 Token

### 4.1 品牌色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ember-600` | `#FF4B1B` | 主 CTA、当前状态、关键强调 |
| `--ember-500` | `#FF6B1A` | 品牌橙、火焰渐变 |
| `--reward-gold` | `#F8B84D` | 积分、成长、奖励、星光 |
| `--cream-100` | `#FFF8EC` | 暖色环境光和浅底 |
| `--ivory` | `#F7F6F3` | 页面基础背景 |
| `--ink-900` | `#1F1F23` | 主标题、关键数字 |
| `--ink-600` | `#5F6068` | 正文和辅助信息 |
| `--line` | `#E8E1D5` | 分隔线 |
| `--ai-cyan` | `#00C2FF` | 仅 AI 状态点缀 |

禁止使用大面积纯蓝、紫色霓虹、彩虹折射或与 Ember 橙竞争的高饱和背景。

### 4.2 圆角

| Token | 建议值 | 用途 |
| --- | ---: | --- |
| `--radius-xs` | `12px` | 标签、状态胶囊、小控件 |
| `--radius-sm` | `16px` | 输入框、次按钮、列表图标 |
| `--radius-md` | `22px` | 普通卡片、券行、筛选器 |
| `--radius-lg` | `28px` | 分组面板、弹层 |
| `--radius-xl` | `34px` | Hero、底部导航、大型玻璃容器 |
| `--radius-pill` | `999px` | Tab Lens、胶囊按钮 |

同类组件圆角必须一致。禁止单页出现 6px、8px 等锐利小圆角，也禁止为了“特别”临时改成异形直角。

### 4.3 间距与触控

- 基础间距单位为 `4px`，常用阶梯为 `8 / 12 / 16 / 20 / 24 / 32px`。
- 页面左右安全边距：手机 `16–20px`；后台桌面 `24–32px`。
- 上下相邻大模块至少保留 `16px` 空隙；顶部 Hero 与下方模块不得粘连。
- 底部导航与最后一个内容模块之间必须保留安全距离。
- 可点击区域最小 `44 × 44px`。

### 4.4 字体

- 小程序页面主标题：`24–28px`，`700–800`。
- Hero 关键数字：`32–40px`，`750–800`。
- 卡片标题：`16–18px`，`650–750`。
- 正文：`14–16px`，`400–550`。
- 标签：`11–13px`，`650–800`。
- 顶部标题和底部导航文字必须清晰醒目，不得为了轻盈感降低到不可读尺寸。

### 4.5 阴影与光

- 基础层：`0 14px 32px rgba(73,43,18,.10)`。
- 悬浮层：`0 22px 44px rgba(73,43,18,.15)`。
- 按压层：`0 8px 18px rgba(73,43,18,.10)`。
- 高光只在主要光源方向出现，不做四边等亮描边。
- 环境光以橙金暖光为主，不使用全屏强发光。

## 5. 材质系统

只允许以下四级材质：

1. **Base Canvas**：暖白基础画布和低对比橙金环境光。
2. **Acrylic Sheet**：分组面板、券组、工具区；轻模糊、低透明、弱边缘。
3. **Liquid Lens**：当前 Tab、主 CTA、选中筛选、AI 主入口；局部折射和内高光。
4. **Solid Ink Surface**：表格、表单、确认区、密集数据；高不透明度和高对比。

同一手机视口最多两个大面积模糊层。列表行不重复使用昂贵模糊，主要依靠暖白半透明填充、分隔和局部高光建立层级。

参考实现：

- `src/prototype/components/Glass.jsx`
- `src/prototype/styles/glass.css`
- `src/prototype/styles/tokens.css`

## 6. 图标与业务对象

普通扁平线性图标不能作为福利、券、积分、余额和关键功能的主图形。业务主图标必须使用透明立体 Glyph：

- 半透明暖白或橙金材质。
- 有前后层次、内高光、软阴影和局部折射。
- 保留清晰的对象轮廓，不能只靠颜色区分。
- 到店券使用火焰尖角。
- 菜品券使用软肉片/花瓣轮廓。
- 聚餐或推荐使用双星连接和软圆弧。
- 饮品券使用液滴玻璃。
- 余额使用液体储值槽。
- 积分和成长使用星币、星芒与成长轨迹。
- 已使用、过期、暂停使用 Ash 雾面和灰烬星点。

业务页面只能向 `RewardGlyph` 传入 `kind / state / value`。如需新增类型，必须先在共享组件中新增语义和三端适配，再进入页面。

## 7. 燎小星身份与场景库

### 7.1 身份校验

任何正式燎小星资产必须同时包含：

- 火焰轮廓。
- 标准五官比例。
- 金色领结。
- 胸前星标。
- 手套和鞋子。
- 橙金披风。

任一项缺失即判定为不合格资产。无披风旧图、带白底图片、比例失真的角色不得进入生产页面。

### 7.2 场景映射

场景库以 `public/brand/ip-liaoxiaoxing/scene-library/manifest.json` 为机器可读唯一映射：

| 场景 | 页面 | 动作语义 |
| --- | --- | --- |
| `home-welcome` | 首页、到店欢迎 | 招手、餐厅欢迎 |
| `benefits-wallet` | 权益、券包、领取成功 | 拿优惠钱包或券 |
| `ai-magic` | AI 创作、生成中、完成 | 星杖和魔法轨迹 |
| `points-reward` | 积分、任务、升级 | 星币和奖励星点 |
| `profile-phone` | 我的、账户、服务 | 拿手机查看账户 |

首页、权益、AI、积分、我的不得使用同一动作图替代。新增商家端或平台场景时，必须先登记到场景库并通过身份校验。

### 7.3 尺寸规则

- 手机顶部 Hero 的角色统一放在 `170 × 170px` 视觉框内。
- 角色使用 `object-fit: contain`，保持原始比例，不得拉伸。
- 同级页面的顶部角色视觉面积保持一致，不得忽大忽小。
- 下方卡片、空态和列表暗纹可以缩小，但不得比文字更抢眼。
- 同一页面最多一个完整角色主视觉。

### 7.4 隐藏暗纹

权益券卡和“我的服务”等列表的右箭头下方，允许使用燎小星局部隐藏形象：

- 透明度 `0.04–0.09`。
- 不影响箭头和文字对比度。
- 裁切后只露出火焰轮廓、披风或星标的一部分。
- 不接收点击，不进入可访问性树。
- 所有暗纹必须来自已批准的透明场景资产。

## 8. 交互与动态

### 8.1 基础参数

| 交互 | 参数 |
| --- | --- |
| Hover / 浮起 | 上移 `1–2px`，`220–280ms` |
| Press / 点击 | 缩放 `0.985–0.99`，建议 `0.987` |
| 弹性曲线 | `cubic-bezier(.2,.9,.24,1.18)` |
| Tab Lens | `220–300ms` 弹性滑动 |
| 短尾焰 | Lens 到位后 `80–120ms` |
| 弹层进入 | `220–320ms`，透明度 + 位移 + 轻模糊 |
| 成功反馈 | `600–1200ms`，结束后自动收敛 |

点击反馈必须在用户触点后立即发生，不能只在接口返回后才有变化。滑动和切换不能改变布局尺寸，避免页面跳动。

### 8.2 Galacean 边界

Galacean Effects 只允许用于：

- 领券成功。
- 核销成功。
- AI 生成完成。
- 会员升级。
- 积分兑换或关键任务完成。

普通列表、表格、输入、筛选、设置、后台 CRUD 页面禁止挂载 Galacean。运行时必须按需加载、使用本地场景、组件卸载时销毁，加载失败不得阻塞业务。

### 8.3 减少动态效果

在 `prefers-reduced-motion: reduce` 或小程序对应无动画配置下：

- 取消弹簧、视差、粒子和尾焰。
- 保留静态选中态、成功态和错误态。
- 状态信息不能依赖动画才能理解。

## 9. iOS 与 Android 一致性

两端必须使用：

- 相同的设计稿尺寸、栅格、字阶、圆角、图片比例和组件结构。
- 相同的动效时长、状态机和交互结果。
- 相同的透明 PNG 资产，不为 Android 替换成扁平图标。

`backdrop-filter` 和类似模糊能力只能作为增强：

- 支持时使用 Acrylic / Liquid Lens。
- 不支持或性能不足时回退到 `92–96%` 不透明暖白表面、浅边缘和标准软阴影。
- 回退后不得丢失圆角、层级、选中态和品牌色。
- 禁止以“安卓性能”为理由删除交互反馈、缩小燎小星或更换布局。

## 10. CRUD 强制继承规则

以后新增、删除、修改、查询任何模块时，必须依次执行：

1. 在 PRD 中定义对象类型、状态、主操作和风险级别。
2. 选择已有 `GlassSurface` 材质级别。
3. 选择或扩展 `RewardGlyph` 业务语义。
4. 判断是否需要完整燎小星；需要时从 `manifest.json` 选择场景。
5. 使用本文件 Token，不写页面私有颜色、圆角、阴影和动效常量。
6. 同时实现正常、加载、空、错误、禁用、成功状态。
7. 验证 iOS、Android、低性能回退和减少动态效果。
8. 生成与同类基准页面一致视口的截图，进入视觉验收。

任何未走完以上步骤的新增页面不得合并。

## 11. 开发实现契约

开发公司必须：

- 以共享组件实现视觉体系，不允许逐页面手写相似样式。
- 保留稳定的组件 API：`GlassSurface`、`LiquidLens`、`RewardGlyph`、`SparkTrail`、`LiaoxiaoxingMoment`。
- 将 Token 放在统一主题文件中，并为小程序 WXSS 和平台 Web 生成等价变量。
- 从场景库 `display/` 使用运行版本，从根目录保留高清母版。
- 记录所有视觉偏差、兼容降级和性能取舍。
- 提交真机截图和录屏，不接受只用开发者工具截图验收。

禁止：

- 使用第三方通用优惠券模板替代燎客券组件。
- 使用 Emoji、随机插画或网络图标替代燎小星和立体 Glyph。
- 把所有容器都做成玻璃。
- 使用白底燎小星图片覆盖玻璃容器。
- 单独修改某一页面主色、圆角或底部导航结构。
- 在未批准节点使用重粒子或循环动画。

## 12. 性能、可访问性与验收

### 12.1 性能

- 手机页面不得横向溢出。
- 同一视口大面积模糊层不超过两个。
- 场景运行图最长边控制在 `600px` 左右，并使用合适压缩格式。
- Galacean 不进入普通页面首屏必需链路。
- 滚动时避免全屏滤镜持续重绘。

### 12.2 可访问性

- 正文与背景保持清晰对比。
- 选中、成功、错误、过期不能只靠颜色表达。
- 点击区域不小于 `44 × 44px`。
- 装饰性暗纹和星点不进入可访问性树。
- 动效关闭后流程完整可用。

### 12.3 P0 视觉验收

以下任一项不通过，视为视觉交付不通过：

- 用户端、商家端、平台后台未使用同一 Token 和共享组件。
- iOS 与 Android 布局、尺寸、页面层级或功能交互不一致。
- 燎小星缺少披风、存在白底、Hero 尺寸不统一或场景动作错误。
- 业务主图标仍为普通扁平图标。
- 圆角、底部安全距离、顶部标题或底部导航不符合规范。
- 玻璃降级后文字、状态或按钮不可读。
- 未实现按压反馈、Tab Lens 或减少动态效果。
- 新页面绕过本规范自行设计。

## 13. 变更治理

本规范锁定后，视觉变更只能通过以下流程：

1. 提交变更原因、影响端和受影响组件。
2. 提交旧版与新版同视口对比。
3. 说明 Token、资产、性能和兼容性变化。
4. 由燎客负责人书面批准。
5. 更新本文件版本、场景库清单、组件实现和验收截图。

未经批准的单页“优化”一律回退。
