# 燎客AI系统 v3.0-MVP 上线验收标准文档

> **文档版本**：v1.0 · **系统版本**：PRD v3.0（抵扣券方案，已删除微信支付分账）
> **适用对象**：小程序开发公司（交付方）、燎客AI创始团队（验收方）
> **生效日期**：双方签字确认后生效

## 第一节：验收文档总览与使用说明

### 优先级定义

| 优先级 | 定义 | 付款影响 |
|:------:|------|---------|
| **P0** | 上线阻断项：任意一条不通过，验收款不支付，上线日期顺延 | 全部通过 → 触发40%验收款 |
| **P1** | 上线前必须完成：可在上线当天修复，但必须在上线后7天内全部通过，否则扣留10%尾款 | 全部通过 → 触发30%尾款（结合P0和稳定运行条件） |
| **P2** | 上线后30天内迭代完成，不影响上线和付款 | 不影响付款 |

**P0项任意一条不通过 = 验收不通过 = 验收款不支付 = 上线日期顺延。** 无例外。

### 验收流程

```
开发方完成自测（所有P0/P1用例自测通过）
 ↓
开发方提交测试环境（含完整交付物清单，见第十节）
 ↓
创始人 + 技术合伙人 按本文档逐项执行验收用例（约2个工作日）
 ↓
出具验收报告（每项标注通过/不通过/待修复）
 ↓
P0项全部通过 + 13个核心用例全部通过 + 压测报告提交
 → 支付40%验收款
 ↓
上线生产环境
 ↓
生产环境稳定运行30天（无P0级故障）+ P1项全部通过 + 基础设施清单全部完成
 → 支付30%尾款
```

### 测试环境要求

- 开发方必须提供独立测试环境，**不得在生产环境执行任何验收测试**
- 测试环境数据库与生产环境**物理隔离**（不同实例，不同账号，不共享任何数据）
- 测试环境须配置真实的阿里云API Key（通义千问Plus + 通义万相V2），不接受mock API替代功能验收
- 所有验收测试须在真实微信客户端中完成，不接受开发者工具模拟

## 延伸说明：上线后第一个月运营监控指标

验收通过是起点，以下指标用于判断系统在真实生产环境中是否按预期运行：

| 周次 | 关键健康指标 | 预警阈值 | 对应处理动作 |
|------|------------|---------|------------|
| 第1周 | 扫码率（扫码人次/进店人次） | <15%连续3天 | 检查桌牌摆放位置和店员引导话术 |
| 第1周 | 老带新订单数 | 0单/周 | 检查推荐关系绑定逻辑是否正常写入 |
| 第2周 | 抵扣券核销率（已使用/已激活） | <20% | 检查券面值和有效期设置，考虑缩短有效期至15天 |
| 第2周 | AI晒圈参与率（晒圈人数/扫码人数） | <10% | 检查激活条件是否过严，检查AI生成成功率 |
| 第4周 | 系统5xx错误率 | >0.5% | 技术合伙人立即排查 |
| 第4周 | 定时任务执行成功率 | <100% | 检查任务告警日志，确认失败原因 |

小程序审核被拒的备用方案：若因余额账户或分销功能被拒，可先上线不含余额功能的基础版本（仅保留扫码进入+领券+AI晒圈），通过审核后更新完整版本。审核材料补充包：余额性质说明函（消费奖励非储值）+ 一级分销合规说明 + 功能截图说明，可向微信审核团队提交申诉 [1]。
