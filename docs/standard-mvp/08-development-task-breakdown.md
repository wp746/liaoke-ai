# 第 8 章：开发任务拆分与排期

## 8.1 角色分工

| 角色 | 职责 |
|------|------|
| 产品/项目负责人 | 确认规则、文案、页面、验收 |
| 小程序前端 | C 端页面、商家端移动页、微信能力 |
| 后端 | API、数据库、AI 网关、核销、统计 |
| UI 设计 | 页面视觉、海报模板、门店品牌感 |
| 测试 | 功能测试、真机测试、并发与异常测试 |
| 运维/后端兼任 | 部署、监控、备份、日志 |

## 8.2 MVP 里程碑

### 第 0 周：准备

- 注册或确认微信小程序主体。
- 准备门店资料：店名、Logo、地址、电话、关键词、福利群链接。
- 确认优惠券规则：今日券、老客奖励券。
- 确认海报模板风格。
- 确认云资源和域名。

### 第 1 周：基础链路

- 数据库建表。
- 门店、桌码、会员基础接口。
- 小程序扫码进入与微信登录。
- 今日券发放与我的券列表。
- 商家端登录和核销入口。

### 第 2 周：AI 图文玩法

- 图片上传。
- AI 文案生成。
- 图片增强。
- 海报生成。
- 素材与 AI 调用记录。

### 第 3 周：裂变与统计

- 海报码参数。
- 邀请关系绑定。
- 新客核销后给邀请人奖励。
- 日统计接口。
- 商家端数据看板。

### 第 4 周：测试与上线

- 真机兼容测试。
- 并发测试。
- 异常测试。
- 微信审核资料整理。
- 门店试运行。

### v3.1 并行迭代：积分兑换模块

- 用户端积分账户、积分商城、兑换记录。
- 商家端积分商品配置与积分兑换码核销。
- 后端积分账户、流水、商品、兑换记录与定时过期任务。
- 验收时必须确认积分不可抵扣现金、不可提现、不可转让。

## 8.8 首版验收标准

必须全部满足：

- 顾客从扫码到领券不超过 10 秒。
- 文案生成常规耗时不超过 4 秒。
- 图片增强常规耗时不超过 10 秒。
- 核销成功率接近 100%，重复核销不会重复优惠。
- 一桌 6 人同时扫码不串用户、不重复错发券。
- AI 失败不影响领券和核销。
- 商家能看到当天关键数据。
- v3.1 积分兑换码可被商家核销，且不改变现金订单金额。
