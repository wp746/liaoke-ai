# 燎客合同体系与关键约束清单

> 版本：v1.0  
> 适用范围：员工、合伙人、商家、外包开发公司、渠道商、供应商  
> 性质：业务约束清单，不是最终法律合同文本  
> 使用方式：交给律师、法务、财务顾问定稿合同前使用

## 1. 合同体系总览

燎客至少需要 8 类合同/协议：

| 编号 | 合同/协议 | 签署对象 | 目的 |
|---|---|---|---|
| C-01 | 劳动合同 | 全职员工 | 明确岗位、薪酬、绩效、保密、知识产权 |
| C-02 | 保密与知识产权协议 | 员工、兼职、外包 | 保护代码、数据、客户资源、品牌资产 |
| C-03 | 合伙人协议 | 技术、销售、运营合伙人 | 明确出资、职责、股权归属、退出 |
| C-04 | 期权/股权激励协议 | 核心员工 | 绑定长期贡献和归属条件 |
| C-05 | 商家试点服务协议 | 试点门店 | 约定试点周期、数据指标、双方配合 |
| C-06 | 商家正式 SaaS 服务协议 | 付费门店 | 约定价格、服务、数据、退款、责任边界 |
| C-07 | 外包开发合同 | 小程序开发公司 | 约定源码、交付物、验收、缺陷、保密 |
| C-08 | 渠道合作协议 | 代理商/城市合伙人 | 约定区域、返佣、客户归属、违规处罚 |

## 2. 员工劳动合同关键条款

必须写清：

- 工作岗位、工作地点、工作内容。
- 薪资结构：基本工资、绩效工资、提成、奖金。
- 工资发放日期。
- 试用期、转正标准、考核方式。
- 社保公积金缴纳口径。
- 保密义务。
- 知识产权归属。
- 客户资源归属。
- 离职交接义务。
- 违纪处理规则。

不建议写：

- “公司可随时无条件调整岗位和薪资”。
- “员工无条件放弃社保”。
- “所有销售提成公司可单方解释”。
- “竞业限制适用于所有员工”。

## 3. 保密与知识产权约束

燎客的核心资产包括：

- 产品 PRD、数据库表结构、接口文档、验收标准。
- 商家名单、联系人、报价、合同、经营数据。
- 用户数据、核销数据、积分数据、邀请关系。
- AI 提示词、行业模板、桌牌设计、燎小星 IP 资产。
- 源代码、部署脚本、密钥、日志、监控数据。

合同中必须约定：

- 员工或外包在工作期间产出的代码、文档、设计、素材、提示词，除另有书面约定外归燎客所有。
- 离职或合同终止后必须归还账号、资料、源文件，不得复制留存。
- 不得私自联系燎客商家转为个人服务。
- 不得将燎客系统、报价、商家数据提供给竞品或第三方。

## 4. 竞业限制边界

竞业限制不能乱用。

建议适用对象：

- CTO/核心后端/核心产品。
- 掌握商家名单、报价体系、渠道体系的销售负责人。
- 掌握完整经营数据和合同体系的高管。

不建议适用对象：

- 普通 BD。
- 普通店员培训运营。
- 初级设计、客服、行政。

必须注意：

- 竞业限制范围要和员工实际接触的商业秘密匹配。
- 地域、期限、行业范围要合理。
- 需要约定竞业补偿。
- 如果员工根本接触不到商业秘密，竞业条款风险很高。

## 5. 合伙人协议关键条款

合伙人不能只靠口头兄弟情。必须写：

### 技术合伙人

- 负责范围：架构、开发管理、代码验收、线上稳定、安全合规。
- 交付节点：v3.1 上线、首批门店稳定运行、后台可用、接口验收通过。
- 股权/期权归属：按时间 + 结果双条件归属。
- 退出：未完成关键交付时，未归属部分自动失效。
- 代码和知识产权归属：全部归公司。

### 销售合伙人

- 负责范围：线索、拜访、签约、回款、渠道。
- 指标：月度签约门店、回款金额、有效渠道数。
- 股权/期权归属：绑定累计净回款、正式付费门店数、低退款率。
- 禁止事项：私收款、私返点、乱承诺、多级分销、保效果。

### 运营合伙人

- 负责范围：商家上线、培训、数据复盘、续费、风险处理。
- 指标：三天上线率、首周活跃、续费率、商家满意度。
- 股权/期权归属：绑定续费门店数、活跃率、客诉控制。

## 6. 商家试点协议关键约束

试点协议要保护你，也要降低老板顾虑。

必须写：

- 试点周期：建议 28 天。
- 试点门店、桌数、活动范围。
- 商家配合义务：摆放桌牌、培训店员、提供经营数据口径。
- 试点成功指标：扫码率、老带新订单数、核销率，至少提前定义。
- 数据口径：进店人数、核销订单、扫码人数怎么统计。
- 不保证营业额绝对增长，只提供系统和运营服务。
- 试点期结束后是否自动转正式，需要明确。
- 商家停用后的数据导出和删除规则。

不能写：

- “保证每月增长 xx 万营业额”。
- “保证带来 xx 个新客”。
- “未达收益公司赔偿全部损失”。

## 7. 商家正式 SaaS 协议关键约束

必须写清：

- 套餐价格：月付、季付、年付。
- 服务范围：小程序、商家端、运营后台、桌牌配置、培训、数据报表。
- 不含范围：深度定制、收银系统深度对接、线下物料无限重印、广告投放费用。
- 数据归属：商家经营数据属于商家，平台依法处理并提供服务。
- 用户个人信息：必须取得用户授权，遵循最小必要原则。
- 停用/退款：按未服务周期、已产生成本、是否已上线区分。
- 服务中断责任：区分平台故障、微信/云服务/AI API 第三方故障、商家网络问题。
- 禁止商家要求多级分销、提现返利、诱导分享。

## 8. 外包开发合同关键约束

开发公司交付不能只给“能点开的页面”。必须写清：

- 源码归属：小程序前端、后端、数据库脚本、部署脚本、接口文档全部交付。
- 交付物：代码仓库、数据库 SQL、API 文档、部署手册、测试账号、环境变量清单、验收报告。
- 验收依据：以 PRD v3.0、积分 v3.1、接口文档、数据库 SQL、验收标准为准。
- 禁止硬编码真实密钥。
- 生产环境和测试环境隔离。
- 缺陷修复期：上线后至少 30-90 天。
- 代码不得包含第三方侵权素材或未授权 SDK。
- 逾期、重大缺陷、源码不交付的违约责任。

## 9. 渠道合作协议关键约束

渠道合作最容易失控。必须写：

- 客户归属：线索报备时间、有效期、冲突处理。
- 区域授权：是否独家，独家条件是什么。
- 返佣：按实收款、净收入还是合同额计算。
- 禁止私自改价、私自承诺、私收款。
- 禁止渠道拿燎客资料做竞品。
- 商家投诉、退款、违规承诺导致的扣佣规则。
- 渠道退出后的客户归属和续费分成。

## 10. 数据与隐私合规约束

燎客会处理用户手机号、openid、消费记录、券/积分记录、邀请关系、图片素材等数据。必须遵守：

- 明示用户协议与隐私政策。
- 处理个人信息要有明确目的、合理范围、最小必要。
- 手机号、生日、消费记录等敏感或重要信息要控制访问权限。
- 不得为了营销过度收集无关信息。
- 用户撤回授权或注销时，要有数据处理流程。
- 商家导出数据要做权限校验和操作日志。

## 11. 产品合规红线

所有合同、培训、销售话术、产品代码都必须统一：

- 老带新只做一级邀请，不做多级分销。
- 老带新奖励用抵扣券，不做微信支付分账，不做现金返利。
- 余额不能提现、不可转让、只能在门店消费抵扣。
- 积分不能提现、不可抵扣现金、不可转让，只能换赠品或服务。
- 不强制用户分享朋友圈。
- 不承诺商家保底增长。
- 不在小程序前端暴露 AI 密钥或数据库密钥。

## 12. 合同归档与权限

建议建立合同台账：

| 字段 | 说明 |
|---|---|
| 合同编号 | 如 LK-MCH-202607-001 |
| 签约对象 | 商家/员工/外包/渠道 |
| 签约主体 | 公司主体名称 |
| 金额 | 合同金额与付款节点 |
| 服务期限 | 起止时间 |
| 负责人 | 销售/运营/项目负责人 |
| 风险条款 | 特殊承诺、退款、定制 |
| 文件地址 | 扫描件/电子签链接 |

权限建议：

- 销售只能看自己客户合同。
- 运营只能看服务所需字段。
- 财务可看金额和开票。
- CEO/法务可看全量。

## 13. 参考来源

- 《中华人民共和国劳动合同法》：关于书面劳动合同、规章制度公示、劳动报酬等。
- 最高人民法院劳动争议司法解释（二）：关于竞业限制、混同用工、社保等。
- 《中华人民共和国个人信息保护法》及网信办公开解读：关于合法、正当、必要、告知同意、最小必要等原则。
